# Feature: mantis-head-3d

Objective: realistic, interactive 3D praying-mantis head in the browser (Three.js) with a continuous skin → metal material transition.
Branch: `feat/mantis-head-3d` · Delivery: `ask-on-risk`, local + GitHub Pages · Test runner: Vitest (logic) + Playwright (visual snapshots).

## Specs

- **S1 — Faithful model.** "Modelo 3D fiel a la guía: anatomía, proporciones y detalles (ojos compuestos, pseudopupila, ocelos, antenas segmentadas, piezas bucales, suturas del exoesqueleto)." Reference sheet: front (primary), right lateral, top, bottom views; head ~35 mm (scene scale 1 unit = 1 cm → 3.5 u). Includes a neck/pronotum stub (approved default).
  - Anatomy to reproduce: triangular head capsule; large lateral ovoid compound eyes with reddish-brown rim; hexagonal ommatidia; dark pseudopupil; three ocelli between the antennae; antennal sockets, scape, pedicel, segmented flagellum with setae; frons with transverse striation; clypeus; labrum; genae; toothed dark-brown mandibles; maxillae with 5-segment maxillary palps; labium with 3-segment labial palps; epicranial and frontoclypeal sutures.
  - Palette: "#8AA84B (verde), #7A8238 (verde oliva), #A8764A (marrón antena), #5C3F2E (marrón oscuro mandíbulas), #4A4644 (gris oscuro), #E6D2C0 (crema)".
- **S2 — Interaction.** "Escritorio: rotar (arrastrar), zoom (rueda), paneo (clic derecho o modificador). Móvil: rotar con un dedo, pinch para zoom, dos dedos para paneo. Límites de cámara razonables, inercia/damping suave y botón de \"reset de vista\". Accesos rápidos a las vistas de la guía (frente, lateral, superior, inferior)."
- **S3 — Skin → metal.** "Un slider que transicione de forma continua entre el exoesqueleto orgánico y un acabado metálico. Presets de metal (por ejemplo: cromo, oro, cobre, bronce envejecido, titanio). Controles extra opcionales: rugosidad, intensidad del relieve, tono, iridiscencia del ojo." "interpolar metalness, roughness, color base, normal/relieve y reflejos; idealmente con un efecto de \"avance\" del metal sobre la superficie (máscara de ruido/disolución)." Eyes metallize too but keep the ommatidia pattern (approved default).
- **S4 — Realism.** "iluminación PBR, mapa de entorno HDRI, sombras suaves, oclusión ambiental, subsurface/translucidez sutil en la piel, brillo especular húmedo en ojos, tone mapping y postprocesado moderado." Dark gray background like the reference, with contact shadow (approved default).
- **S5 — Performance.** "objetivo ~60 fps en escritorio, ≥30 fps en móvil" "con niveles de calidad adaptativos."
- **S6 — Delivery.** Runs locally (`vite dev` / `vite preview`) and is deployed to GitHub Pages (static build, correct `base` path, GitHub Actions workflow).
- **S7 — Working mode.** "Trabajaremos una fase por vez: al terminar cada fase, muéstrame el resultado, resume lo hecho y espera mi confirmación antes de pasar a la siguiente."

## Technical decisions (approved)

- Modeling: approach B hybrid — head capsule/eyes/plates generated by headless Blender scripts (`bpy`) with SubD + procedural displacement, baked maps; antennae and palps parametric (one segment instanced along a curve); ommatidia in shader. GLB stays open to a manual sculpt pass later.
- Tooling: Blender 4.5.15 LTS at `~/opt/blender-4.5.15-linux-x64`, symlinked as `~/.local/bin/blender` (headless + GLB export smoke-tested).
- Textures: baked albedo, normal, roughness, AO, thickness, RGBA zone mask (eye / suture / cavity / mouthparts); 2K/4K → KTX2 (gltf-transform), mesh → meshopt.
- Eye shader: hex grid in eye UV space, view-dependent pseudopupil, clearcoat, iridescence; `fwidth` anti-aliasing.
- Skin → metal: single `MeshPhysicalMaterial` extended via `onBeforeCompile`, uniform `uProgress`; `mask = smoothstep(p - w, p, noise + gradient)` (grows from mandibles to vertex) with a thin front-edge band; interpolate albedo→F0, metalness, roughness, normal strength, translucency off. Presets chrome, gold, copper, titanium, aged bronze (verdigris in cavities via AO). No shader recompilation while sliding.
- Stack: vanilla Three.js + Vite, `WebGLRenderer`, `camera-controls`, `postprocessing` (N8AO, subtle bloom, SMAA, AgX), custom UI + lil-gui in dev only, Poly Haven CC0 studio HDRI, JavaScript with `// @ts-check` + JSDoc.

### Acceptance criteria per phase

- **T0**: damping, distance/polar limits, animated view transitions; works with mouse and touch on a real phone (`touch-action: none`).
- **T1**: silhouette within ~±5% of the 4 orthographic views (front view dominant); correct eye/head ratio.
- **T2**: every S1 element recognizable in front and bottom views; GLB < 3 MB, < 150k triangles at high quality.
- **T3**: palette matches reference; pseudopupil moves with view; no ommatidia aliasing at any distance.
- **T4**: 60 fps desktop at high quality, no stutter while orbiting.
- **T5**: credible at every intermediate value; no recompilation while sliding.
- **T6**: 60 fps desktop, ≥30 fps mid-range phone (user tests on device); first load < 6 MB.
- **T7**: build served from GitHub Pages loads all assets (base path, KTX2 transcoder) without errors.

### Risks

- Script-generated forms may look hard-edged (T2) → SubD + displacement; optional artist sculpt pass.
- Ommatidia aliasing (T3) → `fwidth` filtering + distance fade.
- AO cost on mobile (T4) → disabled on low tier.
- No access to real devices → user validates mobile fps.
- GitHub Pages subpath → Vite `base` and relative asset/transcoder URLs.
